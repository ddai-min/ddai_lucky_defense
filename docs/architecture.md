# 코드 구조와 구현 노트

코드를 읽거나 고치려는 사람을 위한 문서입니다.
게임 자체가 궁금하다면 [README](../README.md), 난이도 수치는 [balance.md](balance.md) 를 보세요.

## 프로젝트 구조

```
lib/
├─ main.dart                       앱 진입점 · 화면 레이아웃(HUD / 게임 / 조작 패널)
├─ game/
│  ├─ lucky_defense_game.dart      FlameGame 본체 — 웨이브·전투·소환·합성 규칙
│  ├─ field_layout.dart            화면 크기 → 몬스터 경로 + 유닛 슬롯 좌표 계산
│  ├─ game_state.dart              자원/웨이브/강화 상태 (ChangeNotifier)
│  ├─ record_store.dart            최고 기록 영구 저장 (SharedPreferences)
│  ├─ leaderboard.dart            모드별 랭킹 (Firestore REST · docs/leaderboard.md)
│  ├─ data/
│  │  ├─ balance.dart              ★ 모든 밸런스 수치
│  │  ├─ game_mode.dart            플레이 방식 (쉬움 · 보통 · 어려움 · 무한)
│  │  ├─ rarity.dart               등급 정의
│  │  ├─ unit_catalog.dart         유닛 도감 + 소환 추첨
│  │  └─ enemy_catalog.dart        몬스터 · 보스 도감
│  └─ components/                  Flame 컴포넌트 (유닛/몬스터/투사체/이펙트/배경)
└─ ui/                             HUD · 조작 패널 · 도감 시트 · 랭킹 시트 · 처치 집계 · 오버레이

firebase/
└─ firestore.rules                 랭킹 보안 규칙 (실제로 위조를 막는 곳)

tool/
└─ balance_sim.dart                난이도 시뮬레이터 ([balance.md](balance.md) 참고)
```

## 실행

```bash
fvm flutter pub get
fvm flutter run            # 또는 ./.fvm/flutter_sdk/bin/flutter run
fvm flutter test           # 게임 로직 + 반응형 레이아웃 테스트
```

세로 화면 기준으로 설계했지만 레이아웃은 화면 크기에 맞춰 계산되므로
폰·태블릿·데스크톱 어디서든 동작합니다.

## 사거리는 픽셀이 아니라 밴드 배수

등급이 오를수록 사거리도 넓어져 신화 이상은 두 칸 건너 레인까지 닿습니다.
이 사거리는 화면 픽셀이 아니라 **레인 간격(밴드)의 배수**로 정의되어 있어
해상도가 달라져도 체감이 같습니다.

## 구현 노트

- **카메라 미사용** — 모든 컴포넌트를 `fieldRoot` 아래 화면 좌표 그대로 배치해 좌표 계산이 단순합니다.
  화면 흔들림은 `fieldRoot.position`을 흔들어 처리합니다.
- **`update()` 안에서 `notifyListeners()` 금지** — Flame의 `GameWidget`은 `update()`를
  `LayoutBuilder` 콜백(빌드 단계) 안에서 호출합니다. 그래서 `GameState.notify()`는
  빌드 중이면 프레임 종료 후로 알림을 미룹니다.
- **리사이즈 가드** — `onGameResize`는 위젯이 리빌드될 때마다 호출되므로,
  크기가 실제로 달라졌을 때만 경로·슬롯을 다시 계산합니다.
- **렌더 캐시** — 그라데이션 셰이더, 점선 슬롯 경로, 배경 격자, 이모지 `TextPainter`를
  캐시해 프레임마다 재생성하지 않습니다.
- **배속(×2/×3)** 은 dt를 키우는 대신 서브스텝을 여러 번 돌려 투사체가 적을 건너뛰지 않게 합니다.
- **넓은 화면** 에서는 앱을 480 폭으로 가운데 세웁니다. 세로 화면 기준으로 만든 게임이라
  그대로 늘리면 필드가 납작해지고 버튼만 길어집니다.
- **슬롯 격자는 고정** 입니다(`FieldLayout.slotCols` · `slotRows`). 화면에 맞춰 칸 수를
  늘리면 기기나 브라우저 확대 배율에 따라 놓을 수 있는 유닛 수가 달라져 난이도가
  통째로 바뀝니다. 칸 수는 고정하고 칸 크기만 늘립니다.
- **스크롤은 마우스로도** 끌립니다(`AppScrollBehavior`). Flutter 기본값은 터치·스타일러스만
  드래그로 인정해서, 웹에서는 가로 목록을 마우스로 잡아끌어도 움직이지 않습니다.
- **일시정지** 는 `update()` 를 `super.update(0)` 한 번으로 갈음합니다. 아예 건너뛰면
  대기 중인 컴포넌트 추가·제거가 처리되지 않아, 마침 그 프레임에 죽은 몬스터가 화면에
  남습니다. dt 가 0 이어도 «쿨타임이 0 이하» 조건으로 발사되므로 유닛·투사체에는
  따로 멈춤 검사를 둡니다.
- **자동 판매 대상** 은 `pickAutoSellIndex` 가 고릅니다. 게임 상태가 필요 없는 순수 함수라
  규칙을 그대로 검증할 수 있습니다. 등급이 가장 낮은 것 중에서 «팔아도 합성 횟수가 줄지
  않는 쪽» 을 먼저 고르고, 그래도 여럿이면 보유 수가 적은 것을 팝니다. 유닛이 영구히
  사라지는 동작이라 누르기 전에 무엇이 팔리는지 패널에 미리 표시하고, 팔아도 골드가
  모자라면 아예 팔지 않습니다.
- **고급소환 대상** 도 같은 방식입니다(`pickHighSummonTarget`). 합성까지 하나 남은 유닛이
  있으면 그걸 콕 집어 주고, 무엇이 나올지 버튼에 미리 띄웁니다. 자리가 없으면 자동 판매가
  먼저 일어나므로 **판 뒤의 보드** 로 계산해야 미리 보기와 실제가 어긋나지 않습니다.
- **단축키** 는 [`GameKey`](../lib/ui/shortcuts.dart) 열거형 하나에서 나옵니다. 키와 화면에
  띄울 글자가 한 칸에 같이 들어 있고, 받아 처리하는 쪽의 `switch` 가 exhaustive 라
  **키만 추가하고 동작을 빼먹으면 컴파일이 막힙니다.** `HardwareKeyboard` 에 직접
  붙여 두었습니다 — 게임 화면에는 글자를 넣는 칸이 없어 키를 가로챌 위젯이 없고,
  Flame 의 `GameWidget` 이 포커스를 가져가도 단축키가 죽지 않습니다. 키캡은 물리
  키보드가 있다고 볼 수 있는 환경에서만 그리지만(`hasPhysicalKeyboard`), 동작 자체는
  어디서나 듭니다 — 폰에 블루투스 키보드를 붙여 쓰는 경우까지 막을 이유는 없습니다.
  꾹 누르고 있으면 골드가 순식간에 빠지므로 자동 반복(`KeyRepeatEvent`)은 받지 않습니다.
  합성(`C`)만은 **고른 유닛이 있을 때만** 듭니다 — `mergeOnce()` 는 인자를 비우면
  «합성 가능한 아무거나» 를 집으므로, 그대로 흘려보내면 어려움에서 누른 적 없는
  초월 도박이 터집니다. 그래서 키캡도 조작 패널이 아니라 선택 카드 위에 붙습니다.
- **유닛별 처치 수** 는 마지막 일격을 넣은 쪽에 붙습니다. 피해를 주는 모든 경로에
  `by`(유닛 도감 id)를 실어 보내는데, 까다로운 건 **중독**입니다 — 도트가 터지는
  시점에는 유닛이 이미 딴 데를 때리고 있거나 팔려서 없을 수도 있어, 몬스터가
  «누가 걸었는지» 를 들고 있어야 합니다(`EnemyComponent._poisonBy`). 더 센 중독이
  덮어쓰면 출처도 같이 바뀝니다. 집계는 판이 끝날 때까지 남으므로 팔거나 합성해
  사라진 유닛의 몫도 그대로 보입니다 — «이번 판에 무엇이 일했나» 를 보는 것이지
  «지금 뭘 들고 있나» 를 보는 게 아닙니다.
- **드롭다운은 `Positioned` 에 `bottom` 까지 줍니다.** `top` 만 주면 Stack 이
  높이를 unbounded 로 넘겨, 목록이 길 때 오버플로 없이 **조용히 필드 밖까지**
  그려집니다. 아래를 묶어 둬야 `LayoutBuilder` 가 실제 여유 높이를 보고 패널을
  줄일 수 있습니다. 늘어난 빈 칸은 포인터를 먹지 않으므로 그 아래 게임 화면은
  그대로 눌립니다.
- **최고 기록** 은 `RecordStore` 인터페이스 뒤에 있습니다. 실제 저장은 `PrefsRecordStore`가,
  테스트는 `MemoryRecordStore`가 담당하므로 플러그인 목 없이도 갱신 규칙을 검증할 수 있습니다.
  저장소 I/O는 `onLoad`를 막지 않도록 백그라운드로 돌리고, 읽기/쓰기 실패는 삼켜서
  저장소를 못 쓰는 환경에서도 게임이 그대로 동작합니다.
  게임오버 시점뿐 아니라 앱이 백그라운드로 갈 때도(`AppLifecycleListener`) 기록을 제출해,
  죽지 않고 앱을 닫아도 진행도가 남습니다.
